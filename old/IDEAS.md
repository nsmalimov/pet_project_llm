# Пять идей для pet/startup-проекта в области LLM / coding agents

Контекст: один сильный backend-разработчик, Go + минимальный frontend, локально-first,
не generic agent framework, целевая аудитория — люди, активно работающие с coding agents
(Claude Code, Codex CLI, Cursor и т.п.).

Для каждой идеи: боль → как работает → MVP → wow-сценарий → риски → куда расти → оценка.

---

## 1. Hindsight — ретроспективы агент-сессий → правила для CLAUDE.md

*(частично уже реализована в этом репо: парсер транскриптов + friction report работают)*

**Боль.** Агент в каждой новой сессии наступает на одни и те же грабли: не тот пакетный
менеджер, не та команда тестов, лезет туда, куда запрещали. Всё это уже происходило в
прошлых сессиях — пользователь исправлял агента руками, но эти исправления умирают вместе
с сессией. `CLAUDE.md` никто не ведёт систематически. При этом каждая коррекция
пользователя, каждый цикл падающей команды — это готовый обучающий сигнал, который просто
лежит в `~/.claude/projects/**/*.jsonl` и гниёт.

**Как работает.**
- Go CLI без зависимостей читает JSONL-транскрипты Claude Code.
- Детерминированный слой (без LLM, мгновенно): статистика инструментов, циклы падающих
  команд («агент 5 раз подряд запускал `npm test` с одной и той же ошибкой»), прерывания
  пользователем, отказы в permissions, токены/стоимость.
- LLM-слой: компактированный транскрипт + friction report → `claude -p` (zero-config,
  переиспользует авторизацию Claude Code, ключи не нужны) → структурированный JSON с
  конкретными правилами уровня «Use pnpm, not npm» с evidence из транскрипта.
- `hindsight distill --write` дописывает принятые правила в `CLAUDE.md` проекта с дедупликацией.

**MVP (реалистично за сессию).** `list` / `report` / `distill --write`. Уже собирается и
`report` работает на живой сессии.

**Wow-сценарий.** Заходишь в любой проект, где гонял Claude Code, пишешь `hindsight
distill --write` — через 30 секунд в CLAUDE.md появляются 3–5 правил, которые ты сам бы
никогда не сел записывать, с доказательствами: «в сессии от 10 августа ты трижды
поправлял агента, что миграции запускаются через make, а не напрямую».

**Риски / конкуренты.**
- Anthropic может встроить это в Claude Code нативно (уже есть `/memory`, авто-«memories»
  экспериментируются) — главный экзистенциальный риск.
- Качество правил зависит от богатства транскриптов: на «гладких» сессиях выхлоп пустой
  (это честно обрабатывается: «нечему учиться»).
- Формат JSONL не задокументирован и может меняться между версиями Claude Code.

**Куда расти.** Кросс-сессионный анализ (правила, подтверждённые N сессиями — сильнее);
поддержка Codex CLI / OpenCode / Cursor; MCP-сервер, чтобы агент сам спрашивал «что я
делал не так в этом проекте раньше»; командный режим — общая база правил на команду;
«недельный дайджест»: сколько токенов сожжено на циклы, какие проекты самые проблемные.

**Оценка.** Боль: высокая, узнаваемая. Уникальность: средняя (ниша горячая, но готового
хорошего тула нет). Демо-магия: высокая. Сложность MVP: низкая (наполовину готов).

## 2. Fleet — монитор живых агент-сессий («няня для агентов»)

**Боль.** Люди запускают по 2–5 параллельных сессий Claude Code (worktrees, разные
проекты) и постоянно переключаются: «этот ждёт permission уже 20 минут», «тот застрял в
цикле и жжёт токены», «третий давно закончил, а я не заметил». Терминалы не видно,
нотификаций мало, стоимость не агрегируется.

**Как работает.**
- Go-демон tail'ит все `*.jsonl` в `~/.claude/projects` (fsnotify) — это фактически
  live-стрим состояния каждой сессии.
- Определяет состояние: работает / ждёт permission / ждёт ввода / закончил / похоже
  застрял (heuristics: повтор одинаковых падающих вызовов, нет прогресса N минут).
- Отдаёт: TUI-дашборд (bubbletea) или локальную веб-страницу + push-нотификации
  (macOS `osascript` / ntfy.sh / telegram).
- Опционально LLM-слой: «что сейчас делает каждая сессия» одной строкой.

**MVP.** Демон + TUI со списком сессий, состояниями и алертом «ждёт permission».

**Wow-сценарий.** Запустил три агента, ушёл варить кофе — телефон пикнул: «сессия
api-refactor ждёт разрешения на git push; сессия parser застряла: 4-й раз падает
go test». Вернулся ровно тогда, когда нужен человек.

**Риски / конкуренты.** Тот же риск нативной фичи (Claude Code уже шлёт локальные
нотификации и имеет /statusline; teleport-подобные обвязки появляются). Детекция
«застрял» — эвристики, будут ложные срабатывания. Демо в автономной сессии показать
труднее: нужны живые параллельные сессии.

**Куда расти.** Управление из дашборда (ответить на permission удалённо), мобильный
доступ, агрегация стоимости по проектам/дням, автопаузa зациклившихся сессий.

**Оценка.** Боль: высокая у power-users. Уникальность: средняя, ниша шевелится.
Демо-магия: высокая вживую, низкая в автономном показе. Сложность: средняя
(демон, watcher, TUI — за 20 минут только скелет).

## 3. why — git-археология: «почему этот код такой» (CLI + MCP)

**Боль.** Половина вопросов при чтении чужого/старого кода — не «что делает», а «почему
так». Ответ размазан по git log, blame, revert'ам, MR-обсуждениям. Люди (и агенты!) не
умеют быстро это собирать: blame показывает последний коммит, а не историю решения.
Coding-агенты регулярно «чинят» код, который выглядит странно намеренно — потому что не
знают историю (Chesterton's Fence).

**Как работает.**
- `why path/file.go:120` → Go CLI собирает evidence: `git log -L` по диапазону строк,
  цепочка blame через переименования, связанные коммиты, revert'ы, номера PR/MR из
  сообщений → компактный пакет → LLM → «эта проверка добавлена в 2023 после инцидента X
  (коммит abc123), убирали её в def456 и вернули обратно в ghi789».
- Тот же движок как MCP-сервер: агент перед изменением «странного» кода сам спрашивает
  `why(file, lines)` — и перестаёт ломать намеренные решения.

**MVP.** CLI `why file:line-range` на локальном git, LLM через `claude -p`.

**Wow-сценарий.** Указал на странный `time.Sleep(200ms)` в проде — получил: «добавлен в
коммите fix: race in shutdown после бага #1432; попытка убрать в v2.1 была revert'нута».
Как MCP: агент сам отказался удалять «лишний» retry, процитировав коммит.

**Риски / конкуренты.** Без ссылок на PR/issues (только локальный git) ответы беднее;
интеграция с GitHub/GitLab API тянет OAuth и усложняет «локальный-first». `git log -L`
медленный на огромных репо. Похожие фичи есть у Sourcegraph/Cody, частично у Copilot.

**Куда расти.** GitHub/GitLab обогащение (PR-дискуссии), кэш-индекс истории, «инцидентный
слой» (линковка с постмортемами), режим pre-edit hook для агентов: автоматически
предупреждать при правке кода с «тяжёлой историей».

**Оценка.** Боль: средне-высокая, вечная. Уникальность: средняя. Демо-магия: высокая,
но нужен репозиторий с богатой историей (в этом репо её нет — демо только на чужом клоне).
Сложность MVP: низко-средняя.

## 4. Inbox — локальная очередь задач для coding-агентов («кинул задачу — получил diff»)

**Боль.** Идеи для правок приходят не за рабочим столом: в дороге, на встрече, при чтении
кода с телефона. К моменту возвращения к ноутбуку половина забыта. Cloud-решения (Codex
web, Devin) требуют отдавать код в облако; хочется локально: свой ноутбук, свои ключи,
свой git.

**Как работает.**
- Go-демон с очередью (SQLite). Задача прилетает через CLI (`inbox add "поправь флаки
  тест в auth"`), HTTP endpoint или telegram-бота.
- На задачу: git worktree → headless `claude -p --permission-mode acceptEdits` в
  worktree → результат: ветка + diff + отчёт. Очередь ограничивает параллелизм.
- Мини-веб или CLI для ревью: посмотреть diff, принять (merge/PR) или отбросить (снести worktree).

**MVP.** `inbox add` / демон, исполняющий по одной задаче в worktree / `inbox review`.

**Wow-сценарий.** С телефона в telegram: «добавь rate limiting на /api/search». Через 15
минут — ответ бота с diff'ом и итогом тестов. Дома — `inbox review`, merge.

**Риски / конкуренты.** Самая горячая и конкурентная ниша (Codex cloud, Claude Code web,
куча оберток); отличие «локальный-first» — реальное, но узкое. Безопасность: headless
агент с acceptEdits без присмотра — нужны sandbox-границы. Telegram-бот тянет сетевую
инфраструктуру (хоть и минимальную). За одну сессию реализуем только CLI-путь без
телеграма — wow слабее.

**Куда расти.** Матрица бэкендов (claude/codex), автопрогон тестов как quality gate,
шаблоны задач, интеграция с issue-трекером: «возьми JIRA-таск и сделай draft PR».

**Оценка.** Боль: высокая. Уникальность: низко-средняя (лобовая конкуренция с большими).
Демо-магия: высокая с телеграмом, средняя без. Сложность: средне-высокая (демон,
worktrees, ревью-цикл).

## 5. Recall — поисковик по всем прошлым агент-сессиям (CLI + MCP)

**Боль.** «Я же уже решал это с агентом месяц назад — как тогда починили тот CORS?»
Транскрипты — это личная база знаний решений, но искать по ним нечем: JSONL-файлы,
гигабайты, grep не понимает структуру. И главное — сам агент не имеет памяти между
сессиями: каждый раз решает задачу с нуля, хотя решение лежит в соседнем файле.

**Как работает.**
- Go-индексатор: JSONL → SQLite FTS5 (полнотекст) с полями (проект, дата, роль,
  инструмент, ошибка/успех). Опционально embeddings поверх (позже).
- `recall "flaky test auth"` → релевантные фрагменты сессий с контекстом: что спросили,
  что сработало.
- MCP-сервер с тем же поиском: агент в новой сессии сам делает `recall_search` и находит
  своё же решение месячной давности. Это превращает тул из «поисковика для человека» в
  «долговременную память для агента» — без vector-DB-инфраструктуры.

**MVP.** Индексатор + FTS-поиск + CLI. MCP-обвязка — если останется время.

**Wow-сценарий.** `recall "миграция падала на unique constraint"` → фрагмент сессии
трёхнедельной давности с точным решением. Или: агент в новой сессии пишет «нашёл в
прошлой сессии, что вы решали это через X» — эффект «у моего агента появилась память».

**Риски / конкуренты.** Направление «memory для агентов» перегрето (mem0, Letta, зашитые
memories в Claude Code) — но все они про «абстрактную память», а не про «поиск по твоим
реальным сессиям», это отличие продаётся. Качество FTS-поиска по чат-мусору — нужна
хорошая фильтрация/чанковка, иначе выдача грязная. На этой машине почти нет истории
сессий — демо только на синтетике.

**Куда расти.** Embeddings + гибридный поиск, поддержка других агентов (Codex, Cursor),
автоподмешивание релевантных прошлых решений в контекст новой сессии (hook), приватный
командный индекс.

**Оценка.** Боль: средне-высокая, растёт с числом сессий. Уникальность: средняя.
Демо-магия: средняя (без реальной истории сессий — синтетика). Сложность: средняя.

## Сравнение

| | Боль | Уникальность | Wow-демо за сессию | Потенциал роста | Сложность MVP | Риск «съедят платформы» |
|---|---|---|---|---|---|---|
| 1. Hindsight | высокая | средняя | **высокое** (реальные данные под рукой) | высокий | **низкая, уже наполовину готов** | высокий |
| 2. Fleet | высокая | средняя | низкое автономно (нужны живые сессии) | высокий | средняя | высокий |
| 3. why | ср.-высокая | средняя | высокое, но нужен чужой репозиторий | средний | низко-средняя | средний |
| 4. Inbox | высокая | низкая | среднее (без telegram) | высокий | высокая | **очень высокий** |
| 5. Recall | ср.-высокая | средняя | среднее (нет данных на машине) | высокий | средняя | высокий |

**Общие замечания.**
- Идеи 1, 2, 5 — это по сути одна платформа «данные из транскриптов агент-сессий»
  (retro / live / search). Начав с любой из них, остальные две становятся фичами того же
  продукта — это плюс к потенциалу каждой.
- Идея 4 — самая «стартаповая» по амбиции, но и самая конкурентная и самая дорогая в MVP.
- Идея 3 — самая независимая от экосистемы Claude Code (работает на любом git-репо),
  но её демо требует репозитория с богатой историей.

## Моя рекомендация

**№1 Hindsight**, по трём причинам:
1. Единственная идея, у которой wow-демо гарантированно показывается на этой машине за
   оставшееся время: транскрипты есть (включая текущую сессию), скелет уже собран и
   `report` работает.
2. Самый короткий путь от MVP до «неожиданно полезно»: даже детерминированный отчёт
   без LLM уже даёт инсайт, а LLM-дистилляция правил — это ощутимая магия.
3. Естественная эволюция в платформу: Fleet (№2) и Recall (№5) — следующие фичи на том
   же парсере, что даёт продукту дорогу на год вперёд.

Запасной вариант, если хочется меньше зависимости от экосистемы Claude Code — №3 (why).
